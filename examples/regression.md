# prompt-enhancer 回归清单

用途：改版回归与下轮迭代输入集。运行方式：用当前 SKILL.md 让新鲜运行器依次处理 5 条输入，逐条核对 pass 基线；任何一条不满足即视为回归失败，先修 SKILL 再发布。判定口径：人工或盲审按 5 维度（意图保真 / 假设与默认可见性 / 执行可执行性 / 人审编辑成本 / 追问质量）核对，以下 pass 项为硬性检查点。

## 输入 1：帮我写个周报（简单需求）

- [ ] 不套完整模板：输出一屏内、可直接填改，不给 7 段式规格
- [ ] 默认/代填显式标注（【 】或「默认：X，可改」），不把结构、篇幅写成无标注硬性要求
- [ ] 零追问或 ≤3 追问且带推荐默认（首选直接给可用成品）

## 输入 2：催款邮件（对象 A / 语气别太硬 / 合同逾期条款 / 本周五前）

- [ ] 保留全部用户显式约束
- [ ] 一个默认只对应一个变量，不把两个独立默认混写在同一行（历史教训）
- [ ] 金额/条款号/日期等数据用【 】占位而非追问；含可核对的验收标准

## 输入 3：优化既有小红书 prompt（修复场景）

- [ ] 修复而非重写：保留原句关键表述与全部显式约束（99 元、不要太长、emoji 不多、违规词）
- [ ] 量化值标注来源或默认，如「原要求：不要太长 → 正文 ≤400 字（默认，可改）」

## 输入 4：健身 App 定价调研 + 教练 SaaS 定价建议（复杂/调研）

- [ ] 对标范围默认含"同品类直接竞品"（教练端 SaaS），不只有 C 端 App
- [ ] 追问 ≤3 且互不重叠、每题带推荐默认；选项密度可读不臃肿

## 输入 5：设计 App 会员等级体系（信息过少）

- [ ] 不猜业务类型；或猜测必须标注为「默认，可改」
- [ ] 关键决策（变现模式/核心目标/数据基础）给带理由的推荐默认，可"按默认"一键回答

## 通用 pass 项（所有输入）

- [ ] 不新增用户未授权目标/约束（意图保真）
- [ ] 默认与代填全部显式标注，不冒充用户要求
- [ ] 无废话：删掉不影响结果的句子不出现
- [ ] 无跨输入/跨会话上下文串用
